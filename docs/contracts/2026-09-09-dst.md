# Pinned contract — DST-correct Pacific time (O-001 / F-001)

*Pasted verbatim into every dispatch. Build lane P-A via `/swarm-build`. Branch `swarm`. Deploy HELD.*

## 1. Surface

- Tool name stays `get_current_datetime_pdt` (renaming is a judgment call for meshe — out of scope; record as an O-row).
- Docstring (verbatim, the whole surface):
  > Returns the current date and time in Pacific time (America/Vancouver), formatted as `DayOfWeek Month DD, YYYY HH:MMam/pm TZ`, where TZ is `PDT` or `PST` according to daylight saving. Example: `Saturday April 04, 2026 06:11pm PDT`.
- Output format (exact): `strftime("%A %B %d, %Y %I:%M%p %Z")` with `AM`/`PM` lowercased to `am`/`pm`. Day is zero-padded as today (`April 04`). Hour is 12-hour zero-padded (`06:11pm`, `12:00am` for midnight, `12:00pm` for noon).
- Time source: `zoneinfo.ZoneInfo("America/Vancouver")`. No hardcoded offsets, no literal `"PDT"` in the format string.
- Structure: `server.py` exposes a pure function `format_pacific(dt: datetime) -> str` (accepts aware or naive-UTC datetimes; converts to America/Vancouver) and the tool `get_current_datetime_pdt()` returns `format_pacific(datetime.now(timezone.utc))`.
- Files: `server.py`; `requirements-dev.txt` (new: `pytest`); `tests/unit/test_format.py`; `tests/integration/test_server.py`; `README.md` (output example + Testing section gains `pytest`).

## 3. Required tests (one per line; the test-writer may add more)

Unit (`tests/unit/test_format.py`, pure, fixed datetimes, no clock):
- 2026-07-01 19:11 UTC → `Wednesday July 01, 2026 12:11pm PDT`
- 2026-12-01 20:11 UTC → `Tuesday December 01, 2026 12:11pm PST`
- 2026-03-08 09:59 UTC (just before the 2026 spring-forward at 2:00 PST) → ends with `PST`; 2026-03-08 10:01 UTC → ends with `PDT`
- 2026-11-01 08:30 UTC (just before fall-back) → `PDT`; 2026-11-01 09:30 UTC → `PST`
- midnight local → `12:00am`; noon local → `12:00pm`
- `am`/`pm` lowercase, never `AM`/`PM`
- a naive datetime is treated as UTC
Integration (`tests/integration/test_server.py`, FastMCP in-process, no container, no network):
- the tool list contains exactly one tool named `get_current_datetime_pdt` whose description equals the docstring above
- calling it returns a single text result matching `^(Monday|Tuesday|Wednesday|Thursday|Friday|Saturday|Sunday) (January|February|March|April|May|June|July|August|September|October|November|December) \d{2}, \d{4} \d{2}:\d{2}(am|pm) (PDT|PST)$`
- the source of `server.py` contains no `timedelta(hours=` and no literal `"PDT"` in a format string (static guard for F-001)
